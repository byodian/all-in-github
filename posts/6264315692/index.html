背景与目标

Lyric Connector 是 Windows 桌面程序，项目使用 WPF、Windows Forms 和 WinRT API，目标框架为 .NET Framework 4.8。除了主程序，还要生成 Inno Setup 安装程序和便携 ZIP。

当前开发环境运行在 WSL。项目中的环境规则禁止在 WSL 中运行包含指定构建命令字样的命令，因此本机不负责发行打包。代码推送到 GitHub 后，通过 workflow_dispatch 启动 windows-latest runner，在 Windows 环境完成 Windows SDK 相关编译和安装程序制作。GitHub 将工作流产物先作为临时 artifact 保存，检查成功后，再由 gh release create 上传为版本附件。

本次使用的源码版本为提交 3cbd409，对应 0.2.3 Release。

版本号与发行配置

程序版本写在 LyricConnector.csproj 中。本次版本字段为 0.2.3，程序集和文件版本为 0.2.3.0，平台目标为 x64。

Inno Setup 使用 LyricConnector.iss 生成安装程序。这里的 AppVersion 和 VersionInfoVersion 也要与项目版本同步，否则安装程序名称或文件属性可能与程序版本不一致。

工作流从项目文件读取 Version，以此生成便携 ZIP 文件名，不在工作流中重复维护一个 ZIP 版本号：

$project = [xml](Get-Content .\desktop\LyricConnector.csproj -Raw)
$appVersion = $project.Project.PropertyGroup.Version
Compress-Archive -Path .\artifacts\app\* `
  -DestinationPath ".\artifacts\installer\LyricConnector-$appVersion-win-x64.zip" `
  -CompressionLevel Optimal

Windows runner 上的发行工作流

完整工作流见 windows-installer.yml。它由 workflow_dispatch 手动触发，在 windows-latest 上依次执行以下操作：

  1. 检出指定分支的源码并安装 .NET 8 SDK。
  2. 使用 dotnet publish 将 .NET 桌面程序和依赖输出到 artifacts/app。
  3. 安装 Inno Setup，并调用 ISCC.exe 根据 .iss 脚本生成单用户安装程序。
  4. 将完整应用目录压缩成便携 ZIP，同时单独复制主程序 EXE。
  5. 为 EXE 和 ZIP 计算 SHA-256，并写入 SHA256SUMS.txt。
  6. 使用 actions/upload-artifact@v4 上传四个文件，供后续下载。

关键的工作流命令如下：

jobs:
  package:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 8.0.x

      - name: Publish desktop application
        run: dotnet publish .\desktop\LyricConnector.csproj --configuration Release --output .\artifacts\app

      - name: Install Inno Setup
        run: choco install innosetup --yes --no-progress

      - name: Create setup program
        shell: pwsh
        run: |
          New-Item -ItemType Directory -Force .\artifacts\installer | Out-Null
          & "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" .\installer\LyricConnector.iss

dotnet publish 将应用及部署所需文件输出到指定目录；Inno Setup 再把应用目录封装为安装程序。便携 ZIP 保留完整运行目录，单独的 LyricConnector.exe 适合快速访问，但独立运行时仍需要 ZIP 中的配置文件和资源目录。可参阅 Microsoft 的 dotnet publish 文档 和 Inno Setup 脚本。

触发工作流并校验产物

将源码提交并推送到 main 后，使用 GitHub CLI 启动工作流并等待它结束：

gh workflow run "Windows installer artifact" --ref main
gh run list --workflow "Windows installer artifact" --limit 1
gh run watch <run-id> --exit-status

本次工作流运行记录是 39231263919。任务成功完成，发行产物为：

  • LyricConnector.exe：主程序。
  • LyricConnector-Setup-0.2.3-x64.exe：Inno Setup 安装程序。
  • LyricConnector-0.2.3-win-x64.zip：便携运行目录。
  • SHA256SUMS.txt：前面三个文件的校验值。

下载 artifact 到临时目录后，使用校验清单验证文件完整性：

gh run download <run-id> \
  --name lyric-connector-windows-x64 \
  --dir /tmp/lyric-connector-0.2.3-release

cd /tmp/lyric-connector-0.2.3-release
sha256sum -c SHA256SUMS.txt

本次三个发行文件都返回 OK。Actions artifact 适合在工作流运行之间传递产物；它与用户最终下载的 Release 附件是两个阶段。相关说明见 GitHub 的 workflow artifacts 文档 和 upload-artifact action 文档。

创建 Release

Release 说明通过 Markdown 文件传入 --notes-file，让 GitHub 收到真实换行，避免把字面量 \n 显示在页面上：

gh release create v0.2.3 \
  /tmp/lyric-connector-0.2.3-release/LyricConnector-Setup-0.2.3-x64.exe \
  /tmp/lyric-connector-0.2.3-release/LyricConnector-0.2.3-win-x64.zip \
  /tmp/lyric-connector-0.2.3-release/LyricConnector.exe \
  /tmp/lyric-connector-0.2.3-release/SHA256SUMS.txt \
  --title "Lyric Connector 0.2.3" \
  --notes-file /tmp/lyric-connector-0.2.3-notes.md \
  --target main

如果 GitHub 上还没有 v0.2.3 标签，--target main 会让该标签指向 main 当前提交。这样发布的源码版本和发行文件能够对应。gh release create 的标签及附件参数见 GitHub CLI 官方手册。

发布完成后，用以下命令检查 Release 名称、正文、标签和附件：

gh release view v0.2.3 --json tagName,name,body,assets,url
gh release list --limit 2

本次 v0.2.3 Release 已成为最新发行版，包含安装程序、便携 ZIP、主程序和校验清单。流程核实的是 Windows 工作流成功、发行文件校验通过以及 Release 附件存在；这不等同于在干净 Windows 环境中完成安装验收。

发布要点

  • 先提交并推送代码，再从明确的提交生成产物，避免发布未提交的工作区状态。
  • 项目版本、程序集版本、Inno Setup 版本和 Release 标签保持一致；ZIP 文件名从项目版本读取。
  • 使用 Windows runner 生成依赖 Windows SDK 的程序与安装程序，不在 WSL 本机运行发行打包。
  • 先上传 Actions artifact，再下载并校验 SHA-256，最后发布到 Release。
  • 将多行说明保存在文件中，并通过 --notes-file 传入。
  • 发布后检查 Release 资产和状态；不要仅凭命令返回成功就假设附件齐全。
